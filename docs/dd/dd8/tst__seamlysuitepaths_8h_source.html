36/**
37 * @brief TST_SeamlySuitePaths tests the two lookups seamly2d uses to find the
38 * SeamlyLayout executable.
39 *
40 * SeamlySuitePaths::locateSeamlyLayout() is the install-directory lookup: the
41 * executable flat beside the caller's apps, or inside the "SeamlyLayout"
42 * subdirectory created by the Windows MSI installer (Task 13).
43 *
44 * SeamlySuitePaths::locateSeamlyLayoutDevBuild() is the development fallback
45 * (Task 50): an upward walk from the running executable's directory looking for
46 * a SeamlyLayout build inside the source checkout, Release before Debug.
47 *
48 * SeamlySuitePaths::patternDocumentName() and seamlyLayoutLaunchArguments()
49 * are the seamly2d half of the Layout Mode launch contract (Seamly2D.5): no
50 * handoff file is written — the piece-mode document goes to the SeamlyLayout
51 * process on its standard input, and the arguments say only that
52 * ("--svg-stdin"), plus the name the document is known by
53 * ("--document-name <pattern base name>"). The daughter app's half — that it
54 * accepts exactly that and rejects anything else — is locked by
55 * StartupOptionsTests in src/test/SeamlyLayoutTest.
56 *
57 * Every case runs against a QTemporaryDir populated with dummy files, so the
58 * suite is hermetic — no real installation, settings value, or application
59 * directory is involved.
60 */
