36/**
37 * @brief TST_SeamlyFamilyPaths tests the two lookups seamly2d uses to find the
38 * SeamlyLayout executable.
39 *
40 * SeamlyFamilyPaths::locateSeamlyLayout() is the install-directory lookup: the
41 * executable flat beside the caller's apps, or inside the "SeamlyLayout"
42 * subdirectory created by the Windows MSI installer (Task 13).
43 *
44 * SeamlyFamilyPaths::locateSeamlyLayoutDevBuild() is the development fallback
45 * (Task 50): an upward walk from the running executable's directory looking for
46 * a SeamlyLayout build inside the source checkout, Release before Debug.
47 *
48 * SeamlyFamilyPaths::piecesSvgFilePath() and seamlyLayoutLaunchArguments() are
49 * the seamly2d half of the Layout Mode launch contract (Task 49): the handoff
50 * file is "<pattern>.pieces.svg" beside the pattern, and it is passed as the
51 * single positional argument of the SeamlyLayout process. The daughter app's
52 * half — that it accepts exactly that and rejects anything else — is locked by
53 * StartupOptionsTests in src/test/SeamlyLayoutTest.
54 *
55 * Every case runs against a QTemporaryDir populated with dummy files, so the
56 * suite is hermetic — no real installation, settings value, or application
57 * directory is involved.
58 */
